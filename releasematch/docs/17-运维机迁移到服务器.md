> **版本：** v1.3（2026-07-28）

## 〇、迁移前必读

### 0.1 角色边界（勿混）

| 角色 | 跑什么 | 本次是否迁移 |
|------|--------|--------------|
| **运维机**（本目标） | Ops UI、权威 MySQL、`pipeline`、`generate`、wrangler、测速/增量/TMDB cron、按需 SOCKS | ✅ 迁到 `8.159.152.227` |
| **Jackett VPS** | Docker Jackett + FlareSolverr + `/opt/healthcheck.sh` | ❌ 不迁（见 `servers.local.json`） |
| **公网站点** | Cloudflare Workers Assets | ❌ 不迁（由运维机 wrangler 上传） |

### 0.2 硬约束

| 项 | 要求 |
|----|------|
| Ops 监听 | **仅** `127.0.0.1:8090`；禁止绑公网 |
| 访问方式 | 笔记本 `ssh -L 8090:127.0.0.1:8090 root@8.159.152.227` |
| 业务库 | 全网 **一套权威库**；迁完后旧机停写 |
| 路径 | crontab / systemd / cron 一律 `cd` 到 **PROJECT_ROOT**（三层），不是 git 根 |
| 密钥 | `.env` 中 **CLOUDFLARE_API_TOKEN 勿 push**（GitHub Push Protection 会拒）；运维机本地填写 |
| `.env` 语法 | `KEY=value` **等号后勿留空格**（`RM_OPS_PASSWORD= 123` 会令 bash source 把值当命令） |
| 防双跑 | 测速 / 增量 / TMDB **只在运维机 cron**；Jackett VPS 只留 healthcheck |
| 首传安全 | **勿对空/稀疏 `portal/dist` 正式 wrangler**（CF 对账会删公网缺页） |

### 0.3 变量

| 变量 | 本文取值 | 说明 |
|------|----------|------|
| `OPS_HOST` | `8.159.152.227` | 新运维机公网 IP |
| `OPS_USER` | `root` | SSH 用户 |
| `GIT_ROOT` | `/opt/releasematch/releasematch` | `git clone` 落点（含 `.git`） |
| `PROJECT_ROOT` | `/opt/releasematch/releasematch/releasematch` | 业务根：`wrangler.toml`、`.env`、`.venv` |
| `REPO_URL` | `<私有仓 URL>` | 迁移前填好 |
| `JACKETT_HOST` | `servers.local.json` → `jackett_vps_japan.host` | 现网 Jackett |

### 0.4 推荐顺序

```
Step 1 旧机收工
  → Step 2 新机 apt（或 bootstrap）
  → Step 3 clone + venv（确认三层 PROJECT_ROOT）
  → Step 4 MySQL 方案 A/B
  → Step 5 libtorrent / Node22+wrangler / CF Token（本地）
  → Step 6 连通性
  → Step 7 Ops systemd
  → Step 8 SOCKS（按需）
  → Step 9 crontab（增量勿长期 --prepare-only）
  → Step 10 防双跑
  → Step 11 Jackett 配置一致性（servers ↔ accounts）
  → Step 12 verify 脚本 + 完成勾选
```

### 0.5 2026-07-28 实迁踩坑（必读）

| # | 现象 | 正确做法 |
|---|------|----------|
| 1 | 路径少一层，systemd/`cd` 找不到 `.venv` | 始终以含 `wrangler.toml` 的目录为 `PROJECT_ROOT` |
| 2 | Debian `nodejs`=18，`wrangler` 4 起不来 | NodeSource **22.x** + `npm i -g wrangler` |
| 3 | `CLOUDFLARE_API_TOKEN` 写入 `.env` 后 `git push` 被拒 | **服务器本地**填 Token；仓内留空占位 |
| 4 | MariaDB `sudo mysql` 通，应用 `127.0.0.1` 密码失败 | 为 `root@localhost` 设 TCP 密码，与 `.env` 一致 |
| 5 | Linode 一键部署更新了 `servers`，`accounts.base_url` 仍旧 IP | 跑 `setup_jackett_a4.py` / 同步 Key；`verify` 会查 host 一致 |
| 6 | 增量 cron 长期 `--prepare-only` | 正式期去掉；否则库已更新、公网不更新 |
| 7 | 空 dist `upload_only` | 先全量/足够 generate，再正式上传 |
| 8 | 旧 Jackett IP 不可达时 Step 10 无法 SSH 核查 | 记入待办；换机后补查 VPS crontab |

**一键引导（迁库完成后、在 PROJECT_ROOT）：**

```bash
bash scripts/ops_host_bootstrap.sh                          # dry-run
bash scripts/ops_host_bootstrap.sh --apply --with-wrangler --with-libtorrent
.venv/bin/python scripts/ops_host_migrate_verify.py --expect-host 8.159.152.227
```

## Step 4 — MySQL 迁库（必须）

> 新机 `.env` 指向**唯一权威库**，且 `db status` 与旧机量级一致。

### 4.0 选型

| 方案 | 适用 | 结果 |
|------|------|------|
| **A. dump → 新机**（推荐） | 旧库本机 `127.0.0.1` | 权威在 `8.159.152.227` |
| **B. 旧库远程** | 暂不搬数 | 权威仍在旧机；须防火墙只放行运维机 |

禁止双写。

### 方案 A

**旧机导出（先停 Ops/cron）：**

```bash
mysqldump -h 127.0.0.1 -P 3306 -u root -p \
  --single-transaction --routines --triggers \
  releasematch > /tmp/releasematch-$(date +%Y%m%d).sql
# 可选 tmdbmeta
mysqldump -h 127.0.0.1 -P 3306 -u root -p \
  --single-transaction --routines --triggers \
  tmdbmeta > /tmp/tmdbmeta-$(date +%Y%m%d).sql
scp /tmp/releasematch-*.sql /tmp/tmdbmeta-*.sql root@8.159.152.227:/tmp/
```

**新机导入 + TCP 密码（实迁关键）：**

```bash
ssh root@8.159.152.227
sudo mysql -e "CREATE DATABASE IF NOT EXISTS releasematch DEFAULT CHARSET utf8mb4;"
# 应用走 TCP 127.0.0.1，须密码（unix_socket 的 sudo mysql 不等于应用能连）
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '与.env一致的密码'; FLUSH PRIVILEGES;"
sudo mysql releasematch < /tmp/releasematch-YYYYMMDD.sql
```

**`.env`：**

```bash
cd /opt/releasematch/releasematch/releasematch
# RM_RELEASE_MYSQL_HOST=127.0.0.1
# RM_RELEASE_MYSQL_PASSWORD=...
# RM_MYSQL_* 若用 tmdbmeta 同样指本机
```

旧机迁完后停写。**.env 中的 CF Token 不要 push。**

### 方案 B

旧机放行 `8.159.152.227 → :3306`，`CREATE USER 'root'@'8.159.152.227' …`，新机 `.env` 指旧机 IP。

### 4.x 验收

```bash

source .venv/bin/activate
python -m workflow.run db status
```

```

[ ] db status 行数与旧机一致
[ ] TCP 密码与 .env 一致（方案 A）
```

## Step 7 — Ops systemd

```bash
# 推荐直接：
cd /opt/releasematch/releasematch/releasematch
bash scripts/ops_host_bootstrap.sh --apply
# 或手工 tee unit（WorkingDirectory/ExecStart 必须是 PROJECT_ROOT）：
```

```ini
[Unit]
Description=ReleaseMatch Ops Console
After=network.target mariadb.service
Wants=mariadb.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/releasematch/releasematch/releasematch
ExecStart=/opt/releasematch/releasematch/releasematch/.venv/bin/python -u -m workflow.run ops serve --host 127.0.0.1 --port 8090
Restart=on-failure
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now releasematch-ops.service
ss -ltn | grep 8090   # 仅 127.0.0.1:8090
```

改 `.env` / Python 后：`sudo systemctl restart releasematch-ops.service`。

## Step 11 — Jackett 配置一致性（实迁新增）

一键部署 / Linode 重建后：

1. `servers.local.json` 的 `host` / URL 通常会更新  
2. **`accounts.local.json` 的 `jackett.base_url` + `api_key` 必须同步**（否则 pipeline 仍打旧 IP）  
3. 远程 Jackett：`python scripts/setup_jackett_a4.py`（已支持非 localhost）  
4. 验收：`python -m workflow.torrent_sources.run status` → `reachable=true`  
5. `ops_host_migrate_verify.py` 会 FAIL：`jackett:host_mismatch`

勿把 Jackett URL 改成运维机 IP。

## 故障速查

| 现象 | 处理 |
|------|------|
| `db status` 失败 | `.env` host/密码；方案 A 查 TCP `ALTER USER` |
| 行数 0 | 误空库；重新 dump/restore |
| Jackett 不可达 / SYN-SENT 旧 IP | Step 11：对齐 accounts↔servers；A4 |
| Ops 起不来 | `journalctl -u releasematch-ops -n 50`；WorkingDirectory 是否少一层 |
| wrangler Authentication | 本地 `.env` Token；`ensure_cloudflare_deploy_env` |
| push 被 Secret scanning 拒 | 从 commit 去掉 Token；服务器本地保留 |
| 公网页缺测速 | 测速后须 generate / 增量 worker；查 `generated_at` vs `slot_speed_summary.updated_at` |
| 公网页大量 404 | 可能稀疏 dist 上传对账删除 → 全量 generate 再 deploy |
| Nyaa/DMHy 超时 | Step 8 SOCKS |
| 测速双份 | Step 10 残留 cron |
