## 〇、迁移前必读

### 0.1 角色边界（勿混）

| 角色 | 跑什么 | 本次是否迁移 |
|------|--------|--------------|
| **运维机**（本目标） | Ops UI、权威 MySQL、`pipeline`、`generate`、可选 wrangler、测速/增量/TMDB cron、按需 SOCKS | ✅ 迁到 `8.159.152.227` |
| **Jackett VPS** | Docker Jackett + FlareSolverr + `/opt/healthcheck.sh` | ❌ 不迁（见 `servers.local.json`） |
| **公网站点** | Cloudflare Pages 静态站 | ❌ 不迁 |

### 0.2 硬约束

| 项 | 要求 |
|----|------|
| Ops 监听 | **仅** `127.0.0.1:8090`；禁止绑公网 / 防火墙全开 8090 |
| 访问方式 | 笔记本 `ssh -L 8090:127.0.0.1:8090 …` |
| 业务库 | 全网 **只有一套权威库**；迁完后旧机 MySQL 只读归档或停写 |
| 密钥同步 | 私有仓 `push` / `pull`（`.env`、`accounts.local.json`、`servers.local.json`） |
| 路径约定 | 默认 `/opt/releasematch`；crontab / systemd 路径须一致 |
| 防双跑 | 测速 / 增量 / TMDB **全网只在一处 cron**（新运维机）；Jackett VPS 上若有同名任务须删 |

### 0.3 变量（全文替换用）

| 变量 | 本文取值 | 说明 |
|------|----------|------|
| `OPS_HOST` | `8.159.152.227` | 新运维机公网 IP |
| `OPS_USER` | `root` | SSH 用户（按实改） |

## Step 4 — MySQL 迁库（必须）

> **目标：** 新运维机上的 `.env` 指向**唯一权威库**，且 `db status` 行数与旧机一致。  
> 当前 Mac `.env` 多为 `RM_RELEASE_MYSQL_HOST=127.0.0.1` → **必须选 A 或 B，不能只 clone 代码。**

### 4.0 选哪条方案

| 方案 | 适用 | 结果 |
|------|------|------|
| **A. dump → 新机 MySQL**（推荐） | 旧库在本机 `127.0.0.1`，希望运维机自包含 | 权威库落在 `8.159.152.227` |
| **B. 旧库改远程可达** | 暂不想搬数据，只让新机连旧机 MySQL | 权威库仍在旧机；旧机须常开且防火墙放行 |

两套库并行写 = **禁止**。

---

### 方案 A — dump / restore 到新机（推荐）

#### A.1 旧机导出（停写窗口）

在旧机（导出前确认 Ops / cron 已停，避免导出中途大写入）：

```bash
# Release 业务库（必迁）
mysqldump -h 127.0.0.1 -P 3306 -u root -p \
  --single-transaction --routines --triggers \
  releasematch > /tmp/releasematch-$(date +%Y%m%d).sql

# 若使用 TMDB 元数据桥接库（.env 里 RM_MYSQL_DB，常见 tmdbmeta）一并导出
mysqldump -h 127.0.0.1 -P 3306 -u root -p \
  --single-transaction --routines --triggers \
  tmdbmeta > /tmp/tmdbmeta-$(date +%Y%m%d).sql

ls -lh /tmp/releasematch-*.sql /tmp/tmdbmeta-*.sql
```

#### A.2 传到新机

```bash
# 在旧机执行（按实改用户）
scp /tmp/releasematch-*.sql /tmp/tmdbmeta-*.sql root@8.159.152.227:/tmp/
```

#### A.3 新机建库并导入

```bash
ssh root@8.159.152.227

# 设 root 密码策略按你环境；以下示例用 mysql 客户端
sudo mysql -e "CREATE DATABASE IF NOT EXISTS releasematch DEFAULT CHARSET utf8mb4;"
sudo mysql -e "CREATE DATABASE IF NOT EXISTS tmdbmeta DEFAULT CHARSET utf8mb4;"
# 若应用用非 root 用户，再 CREATE USER + GRANT（与 .env 一致）

sudo mysql releasematch < /tmp/releasematch-YYYYMMDD.sql
# 若有 tmdbmeta：
sudo mysql tmdbmeta < /tmp/tmdbmeta-YYYYMMDD.sql
```

#### A.4 改新机 `.env`（权威指向本机）

```bash
cd /opt/releasematch/releasematch
# 编辑 .env：
# RM_RELEASE_MYSQL_HOST=127.0.0.1
# RM_RELEASE_MYSQL_PORT=3306
# RM_RELEASE_MYSQL_DB=releasematch
# RM_RELEASE_MYSQL_USER=...
# RM_RELEASE_MYSQL_PASSWORD=...
# 若用 tmdbmeta：RM_MYSQL_HOST=127.0.0.1 等与上面对齐
```

导入完成后 **commit + push** 更新后的 `.env`（仓须 private），避免另一地点又指回旧机。

#### A.5 旧机停写（迁完后）

```bash
# 旧机：确认不再跑 ops / cron 写库后，可选停 MySQL 或改只读
# 至少保证旧机 .env 不再被日常流程使用；勿双写
```

## Step 7 — Ops 常驻（systemd）（必须）

> 前台 `ops serve` 会随 SSH 断开而停。生产用 **systemd** 常驻，仍只绑 `127.0.0.1`。

### 7.1 写入 unit

```bash
sudo tee /etc/systemd/system/releasematch-ops.service >/dev/null <<'EOF'
[Unit]
# ReleaseMatch Ops 控制台（仅本机 8090）
Description=ReleaseMatch Ops Console
After=network.target mariadb.service
Wants=mariadb.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/releasematch/releasematch/releasematch
# 由 workflow 自行读项目根 .env；勿把密钥写进 unit
ExecStart=/opt/releasematch/releasematch/releasematch/.venv/bin/python -u -m workflow.run ops serve --host 127.0.0.1 --port 8090
Restart=on-failure
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
EOF
```

若进程用户不是 `root`，改 `User=` 并保证对 `PROJECT_ROOT` 可读。

### 7.2 启用并验收

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now releasematch-ops.service
sudo systemctl status releasematch-ops.service --no-pager
ss -ltn | grep 8090
# 应看到 127.0.0.1:8090
```

```bash
# 改 Python 路由后：
sudo systemctl restart releasematch-ops.service
# 仅改 ops.js：浏览器硬刷新即可
```

日志：

```bash
journalctl -u releasematch-ops.service -f
```

**勾选：**

```
[ ] systemctl status 为 active (running)
[ ] 8090 仅监听 127.0.0.1
[ ] 笔记本隧道仍可打开 Ops
```

## Step 8 — SOCKS 隧道（按需）

> Nyaa / DMHy 等从运维机直连失败时，经 **Jackett VPS** 建本机 SOCKS5（`scripts/start_ssh_socks_tunnel.sh`）。  
> 日常 Jackett Torznab **不依赖** SOCKS；本步按需，不是每天必开。

### 8.1 确认脚本目标 host

```bash
cd /opt/releasematch/releasematch
# 脚本默认 VPS_HOST 可能过期；以 servers.local.json 为准：
python3 -c "import json; print(json.load(open('workflow/torrent_sources/servers.local.json'))['jackett_vps_japan']['host'])"
```

### 8.2 建立隧道

```bash
cd /opt/releasematch/releasematch
export SSHPASS="$(python3 -c "import json; print(json.load(open('workflow/torrent_sources/servers.local.json'))['jackett_vps_japan']['ssh']['password'])")"
VPS_HOST="$(python3 -c "import json; print(json.load(open('workflow/torrent_sources/servers.local.json'))['jackett_vps_japan']['host'])")" \
  bash scripts/start_ssh_socks_tunnel.sh

export TORRENT_PROXY=socks5h://127.0.0.1:1080
```

需要长期挂着时可用 `tmux`/`screen` 跑隧道，或另写 `releasematch-socks.service`（`ssh -N -D 127.0.0.1:1080`）；**密码勿写进 unit 明文**，改用 SSH key。

### 8.3 停隧道

```bash
pkill -f 'ssh -N -D 127.0.0.1:1080' || true
unset TORRENT_PROXY
```

**勾选：**


## Step 10 — 防双跑（旧机 + Jackett VPS）（必须）

> **双跑：** 同一条 `speedtest_batch_worker` / `incremental_publish_worker` / `ops tmdb-sync` 在两台机器 crontab 同时存在 → 重复测速、抢写 MySQL、日志混乱。  
> **目标：** 上述三条 **只在** `8.159.152.227`；Jackett VPS **只保留** healthcheck。

### 10.1 旧运维机（Mac / 原开发机）

```bash
crontab -l
crontab -e
# 删除含下列关键字的行：
#   speedtest_batch_worker
#   incremental_publish_worker
#   ops tmdb-sync
# 确认不再跑 ops serve（已由新机 systemd 接管）
```

### 10.2 Jackett VPS（防 VPS 双跑）

```bash
# JACKETT_HOST 取自 servers.local.json
ssh root@${JACKETT_HOST} 'crontab -l' | tee /tmp/jackett-vps-crontab-$(date +%Y%m%d).txt
```

在 VPS 上 `crontab -e`：

| 保留 | 删除或注释 |
|------|------------|
| `/opt/healthcheck.sh`（Jackett/FlareSolverr 存活） | `speedtest_batch_worker.py` |
| | `incremental_publish_worker.py` |
| | `workflow.run ops tmdb-sync` |
| | 任何 `cd /opt/releasematch/...` 的测速/增量/TMDB 行 |

```bash
# 复查：不应再出现三条业务 cron
ssh root@${JACKETT_HOST} 'crontab -l | grep -E "speedtest_batch|incremental_publish|tmdb-sync" || echo OK: no duplicate business crons'
```

### 10.3 全网唯一性确认

## 故障速查

| 现象 | 处理 |
|------|------|
| `db status` 失败 | Step 4：`.env` host/密码；方案 B 查防火墙与 `root@'8.159.152.227'` |
| 行数为 0 / 空库 | 误对空库 `db init` 当权威；重新 dump/restore 或改回正确 host |
| Jackett 不可达 | `accounts.local.json` 仍须指向 Jackett VPS；VPS `docker ps` |
| Ops 隧道打不开 | `systemctl status releasematch-ops`；是否 `-L 8090` |
| systemd 起不来 | `journalctl -u releasematch-ops.service -n 50`；WorkingDirectory / `.venv` 路径 |
| `libtorrent` 失败 | `python3-dev` + `libtorrent-rasterbar-dev` 后重装 |
| Nyaa/DMHy 超时 | Step 8 SOCKS + `export TORRENT_PROXY=...` |
| 测速/页面「双份」 | Step 10：旧机或 Jackett VPS 仍残留业务 cron |
| TV 季集路径错 | `export RM_CRAWLER_TMDB_ROOT=/实际路径`（勿沿用 macOS 路径） |
