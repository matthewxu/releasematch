## 一、战略结论（一句话）

> **不做第 N 个 1337x；做「影视 Release 的导航与裁判」。**  
> 数据层聚合 magnet 元数据，产品层卖推荐与可信度，流量层吃长尾 + 分发插件，合规层独立域隔离风险。

**「打败」在现实里不等于流量绝对值超过 TPB**，而是：

1. 在 **「best release / 单集 download」** 意图上稳定进入 SERP 相关结果前区  
2. 用户心智从「找链接」转为「来这里决定下哪个」  
3. 工具产出的 IG（Recommended / 对版 / Group / 测速）成为竞品 TOP10 **无法拼凑** 的增量  

与 [04](./04-方案全景分析与优先级重评.md) §1.1 定位表一致：**页面主语是 Release 决策，不是 magnet 条数。**

## 二、五站竞品画像与护城河

### 2.1 一览表

| 站点 | 核心心智 | 护城河 | 结构性弱点（可打点） |
|------|----------|--------|----------------------|
| **1337x.to** | 「全能下载站」 | 品牌 + 历史外链 + 全品类覆盖 | 页薄、无推荐、SERP 同质、镜像稀释品牌 |
| **thepiratebay.org** | 「BT 鼻祖」 | 极强品牌记忆 + 文化符号 | UX/质量参差、决策零指导、合规与可用性波动 |
| **yts.bz**（及 YTS 系） | 「电影一键 720/1080」 | 极简电影心智、高转化短路径 | 品类窄、质量单一、剧集弱、版本选择浅 |
| **limetorrents.fun** | 「长尾收录」 | 页量 + SEO 铺量 | 薄页多，2026 IG/HCU 下脆弱 |
| **ext.to** | 「扩展索引」 | 覆盖面与索引广度 | 同质清单、低信任、易被算法当 scaled content |

### 2.2 他们共同拼什么

```
竞品等式 ≈ 链接数 × 域名权重 × 品牌记忆 ×（广告变现）
```

按同一等式竞赛，新站几乎必输。ReleaseMatch 必须换等式：

```
RM 等式 ≈ 决策质量 × 独有 IG × 长尾 CTR × 分发回访
         （Recommended + 对版 + Group + 测速）
```

### 2.3 与全球 SERP 格局的衔接

详见 [全球SEO流量定位.md](./全球SEO流量定位.md) §五。本文档只固化对上述五站的 **不拼 / 应拼**：

| 竞品类型 | **不拼** | **应拼** |
|----------|----------|----------|
| 1337x / TPB 系 | 链接数量、更新速度、L1 泛词 | Recommended + 理由 + 停留 |
| YTS 系 | 「一键两个画质」的极简抄袭 | 电影多版本对比 + 剧集心智空缺 |
| Lime / EXT 系 | 薄页铺量、镜像互链 | 精品槽 + 薄页门禁 + 实测 IG |

## 三、功能差距矩阵（竞品 vs ReleaseMatch）

> 用途：排期争论、页面验收、PR 合并前对照。落入「竞品列」且无 RM 增量的能力，默认 **不做或延后**。

| 维度 | 五站典型做法 | ReleaseMatch 目标态 | 可执行决策 | 主轨道 |
|------|--------------|---------------------|------------|--------|
| **产品心智** | 「这集/这部有多少下载链接」 | 「该下哪个 release、为什么」 | 文案与 UI 以 **Release 决策** 为主语 | 产品 / C |
| **页面核心单元** | magnet 行（名 + size + seeders） | **槽位** + Recommended 主角卡 | 一页一槽位；列表是辅助 | T3 / C1 |
| **选择指导** | 无或仅 quality 标签 | Recommended + 对版说明 | 无推荐理由的页 **不得 index** | T1 |
| **可信度** | 用户自行判断 | Group 信誉 + 跨源一致性 badge | 写入 HTML，非事后手填 | T1 |
| **可用性** | seeders 数字（常过期） | libtorrent / 多地测速 IG | 核心槽优先测速覆盖 | T2 / T5 |
| **电影体验** | YTS：720/1080 两档 | All Versions 分组对比 + 单条 REC | 不抄 YTS 两档极简当唯一卖点 | T3 / C |
| **剧集体验** | 弱或按种子名堆砌 | 单集槽位 + SxxExx 长尾 | 冷启动以剧集单集为主战场 | C1~C4 |
| **收录规模** | 数万~数十万薄页 | M12 **5K~10K** 精品页 | 收录率 &lt; 25% 不启 C4 扩页 | C |
| **SEO 词** | L1/L2 泛词 + 镜像站群 | L3/L4 长尾 + brand | 放弃 L1 泛词主攻 | SEO |
| **分发** | 几乎纯 Web | Web + Stremio + 扩展 | T4 与 SEO 互补，非替代 | T4 |
| **稀缺/区域** | 偶发、无产品化 | 稀缺槽 + 华语/日韩叙事 | 见 10 / 11 号文档 | C / 规划 |
| **数据与托管** | 部分混同「提供下载」 | **仅元数据索引** | 禁止代下、禁止主域 `/download/` | 合规 |
| **成功指标** | UV、页数、magnet 条数 | IG 覆盖率、Recommended 率、长尾 CTR | 验收看 JSON/HTML 字段，不看条数 | 全员 |

### 3.1 同槽位示意（Breaking Bad S04E06）

```
竞品（典型 magnet 聚合站）：
  Breaking.Bad.S04E06.1080p.WEB-DL.GROUP-X   2.4 GB   24 seeders
  Breaking.Bad.S04E06.720p.WEB-DL.GROUP-Y    1.1 GB   18 seeders
  ← 只有清单，无推荐、无对版依据

ReleaseMatch：
  ⭐ Recommended: GROUP-X  1080p WEB-DL  2.4 GB  24 seeders
     理由：Scene 合规；Amazon Prime US WEB-DL；DDP5.1 经校验无延迟
     Group badge：A 级 · 跨源 3/3 一致 · 测速 4.2 MB/s
  All Sources（8 matched）…
  ← 多 3~5 条竞品页无法拼凑的增量信息
```

## 四、战场划分：不拼什么 / 拼什么

### 4.1 明确不拼（资源禁止投入）

| 禁止项 | 原因 |
|--------|------|
| L1 泛词（`torrent`、`pirate bay`、站点品牌词对打） | 权重与品牌碾压，ROI 为负 |
| 6 万+ 薄页铺量、Skyscraper 洗稿 | Scaled Content Abuse + 零 IG |
| 纯 magnet 条数竞赛 | 与竞品同源时无差异 |
| 镜像站 / sitewide 互链灌权重 | Site Reputation Abuse、合规风险 |
| 代下载、视频托管 | 合规红线 |
| 照搬 YTS「仅两档画质」当全站唯一模型 | 放弃剧集与多版本决策优势 |

### 4.2 明确要拼（主战场）

| 战场 | 用户问题 | RM 武器 | 主要对手弱点 |
|------|----------|---------|--------------|
| **I2 选择** | 下哪个 release？ | Recommended + 对版 | 五站均弱 |
| **I3 验证** | 会不会错版/枪版？ | 跨源 badge + Group | 五站几乎无 |
| **I4 可用性** | 还能下吗、快吗？ | 测速 IG | seeders 过期/虚高 |
| **剧集单集长尾** | `s04e06 download` | 槽位页精品化 | YTS 剧集空缺；聚合站决策空缺 |
| **电影版本对比** | WEB-DL vs BluRay vs REMUX | All Versions | YTS 过简；聚合站过乱 |
| **分发路径** | 播的时候直接选流 | Stremio / 扩展 | 五站几乎不做站外决策层 |
| **稀缺/区域** | 华语/日韩难找 | 10 / 11 叙事 | 五站非产品化 |

### 4.3 流量截流公式（SEO）

> 用 **「download / sources」长尾拿点击**，用 **Recommended + 测速 + Group 信誉拿排名与停留**；  
> 不跟 1337x 镜像站拼链接数，不做 L1 泛词铺量。

与 [全球SEO流量定位.md](./全球SEO流量定位.md) §1.1 一致。

## 五、作战方案（四阶段）

阶段与 [04](./04-方案全景分析与优先级重评.md) 双轨对齐：**工具先行，内容延后；无 IG 不扩页。**

### Phase A — 工具壁垒（先于规模）

| 目标 | 关键交付 | 门禁 |
|------|----------|------|
| 数据稳定 | T0 多源归一化、槽位管道 | 核心源可重复拉取 |
| 决策引擎 | T1 Recommended + 对版 + Group **自动写入** | 页含 `is_recommended` / `recommend_reason` |
| 可用性 IG | T2 核心槽测速覆盖 | 验收集测速字段非空率达标 |
| 生成器 | T3 槽位 → 带 IG 的 HTML | C1 验证集与后续规模 **共用生成器** |

**原则：** 无 IG 模块的页 **不得 index**；≥2 magnet 薄页门禁。

### Phase B — 冷启动 SEO

| 目标 | 关键交付 | 门禁 |
|------|----------|------|
| Trust / 技术壳 | C0 独立域、Trust 四页、robots/canonical/sitemap、DMCA 410 | 壳页可审 |
| 验证集 | C1 验证集做透（推荐完整页） | 人工抽检 IG 可见 |
| 收录启动 | C2 GSC 提交 | **T3 前禁止批量可索引扩页** |
| 节奏 | M1~M3 沙盒期不盲目增页 | 收录率健康再进 C4 |

**M12 量级预期（中性，非对标 TPB）：** 5K~10K 精品页，日 UV 约 500~1,200（见 01 §12.8）。

### Phase C — 竞品缺口收割

| 缺口来源 | 打法 | 优先对标 |
|----------|------|----------|
| 剧集「下哪个版」 | 单集槽位 + Recommended 主角卡 | 1337x / TPB / Lime / EXT |
| 错版焦虑 | 跨源 + 对版说明 | 全员 |
| 快不快 / 能不能下 | 测速 IG | 全员 |
| YTS 只覆盖电影 | 剧集为主战场；电影做多版本对比 | YTS |
| 站内体验噪音 | 一页一决策，少广告式干扰 | 聚合站 |
| 区域稀缺 | 华语 / 日韩 / 求片（10、11） | 五站非产品化部分 |

### Phase D — 增长杠杆（规模之后）

| 杠杆 | 作用 | 轨道 |
|------|------|------|
| Stremio 插件 | 把「决策」嵌进播放路径；品牌与回访 | T4 / [09](./09-Stremio插件价值分析.md) |
| 浏览器扩展 | 站外辅助选版 | T4 |
| 稀缺槽 / 求片通知 | 供给侧第二叙事 | [10](./10-稀缺槽与用户求片通知方案.md) |
| Community Verified | 有量后的信任增强 | C4 后 |
| 编码 Phase 2 / 多地测速 | IG 加深 | T5 |

## 六、90 天执行清单

> 假设从「工具已部分就绪、内容未大规模 GSC」的常见基线出发；若某项已完成，勾掉并前移下一项。日期以启动日为 D0。

### D0~D30 — 壁垒闭环（Phase A 收口）

| # | 动作 | 完成标准 | 关联 |
|---|------|----------|------|
| A1 | 验收 Recommended 自动写入率 | 验证集页 100% 有 REC + reason | T1 / IG 登记册 |
| A2 | 跨源 consistency / Group badge 上页 | HTML/JSON 可机读抽检 | T1 |
| A3 | 核心验证槽测速 | 约定 N 槽测速字段非空 | T2 |

| A5 | 生成器与验证集同源 | 改 scorer 后重生成即可反映 | T3 |
| A6 | Trust + DMCA 410 可用 | 人工走通一条 410 | C0 |

### D31~D60 — 冷启动与意图占位（Phase B）

| # | 动作 | 完成标准 | 关联 |
|---|------|----------|------|
| B1 | 验证集 SEO 技术项 | title/H1/canonical/内部链符合 01/全球SEO | C1~C2 |
| B2 | GSC 属性与首批 URL Inspection | 首批可 index 页进入提交节奏 | C2 |
| B3 | 剧集长尾词簇对齐 | 验证集覆盖语义簇 A 主模板 | 全球SEO §六 |
| B4 | 电影页差异化（非 YTS 两档抄袭） | All Versions + 单条 REC 可验收 | 全球SEO §6.3 |
| B5 | 收录率周报 | 低于阈值则 **停扩页、修 IG/技术** | 01 / 12 手册 |

### D61~D90 — 缺口收割启动（Phase C 前置）

| # | 动作 | 完成标准 | 关联 |
|---|------|----------|------|
| C1 | 选槽：高意图剧集 + 少量电影标杆 | 选槽表符合 Portfolio 标准 | 全球SEO §八 |
| C2 | 小批量可 index 扩页（非 C4 冲量） | 每批后看收录与 CTR，不盲扩 | C2~C3 |
| C3 | 对五站 SERP 抽样对比 | 同 query 下 RM 是否多出独有模块 | 本文 §三 |
| C4 | Stremio / 扩展里程碑评审 | 是否进入 T4 开工（门禁：站内 IG 稳定） | 09 |
| C5 | 稀缺/华语是否开第二条叙事 | 决策记录（开 / 暂缓） | 10 / 11 |

### 90 天结束时的「过关」条件（须同时满足）

1. 验证集与已提交页：**Recommended 覆盖率达标**（团队自定阈值，建议验证集 100%）  
2. **无 IG 页未进入可 index 集合**  
3. GSC：**无因薄页/scaled content 的明显负面手动或结构性崩盘信号**  
4. 至少完成 **1 次** 同 query 五站 vs RM 的 IG 差距书面记录（可进 worklog）  
5. T4 / 稀缺叙事有 **明确 go / no-go**，不悬空

## 七、KPI 与「打败」的可判定定义

### 7.1 错误 KPI（禁止作为主北极星）

| 错误 KPI | 为何错误 |
|----------|----------|
| magnet 总条数 | 与竞品同源时无产品意义 |
| 总页数对标 Lime/EXT | 鼓励薄页自杀 |
| 日 UV 对标 1337x / TPB | 品牌与历史权重不可短期复制 |
| 镜像数量 / 互链数 | 合规与算法双杀 |

### 7.2 正确 KPI（分层）

| 层级 | 指标 | 用途 |
|------|------|------|
| **产品 IG** | Recommended 覆盖率、每页 IG 信号数、测速覆盖率、跨源一致率 | 工具轨验收 |
| **SEO 健康** | 可 index 页收录率、长尾 CTR、索引膨胀/掉收 | 内容轨门禁 |
| **体验** | 停留、回访、REC 点击/出站占比 | 决策是否被使用 |
| **分发（后期）** | Stremio 安装/调用、品牌词搜索 | Phase D |
| **战略结果** | 目标意图词簇上的可见度（非全站 UV） | 「打败」判定 |

### 7.3 「打败」三阶定义（写进评审用）

| 阶 | 定义 | 典型时间感 |
|----|------|------------|
| **L1 局部打赢** | 验证集/标杆剧在若干 L3 长尾上，RM 页提供的决策模块显著优于五站同 query 页，且开始有稳定展示 | 冷启动后 |
| **L2 意图打赢** | 「best release / 单集 download」词簇上，RM 成为用户可复述的备选心智（品牌词或回访上升） | M6+ 量级 |
| **L3 品类打赢** | 剧集单集决策场景中，RM 在目标市场可见度与转化路径上稳定优于「纯清单站」；**不要求**总流量超过 TPB/1337x | M12 战略验收 |

**评审时必须回答：** 当前处于 L1 / L2 / L3 哪一阶？证据是 IG 与意图可见度，不是总 UV。

## 八、风险与禁止事项

| 风险 | 表现 | 对策 |
|------|------|------|
| 做成第 N 个聚合站 | 功能排期又回到「多爬源、多铺页」 | 用 §三矩阵否决；回 04 自检六问 |
| 过早 C4 扩页 | 收录率崩、被当 scaled content | 收录率门禁；无 IG 不 index |
| 抄 YTS 极简当终点 | 丢掉剧集与多版本优势 | 电影页保留 All Versions + REC |
| 站群/主域耦合 | Site Reputation Abuse、连坐 | 独立域；字幕站仅单集 1 链 |
| 忽略合规 | DMCA 无 410、代下 | C0 工作流；元数据-only |
